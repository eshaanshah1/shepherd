# Multiple Tabs Per Task — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A task owns a *group* of layout roots instead of one, so it can hold several tabs — drawn as a strip above the stage and as a capped sublist under its sidebar row, each tab with its own status dot, and each reachable from a remote member.

**Architecture:** `RootState` gains one opaque `group: string` field, defaulting to the root's own id — so every existing root becomes a group of one and nothing changes until somebody groups two. Tabs are then roots that share a group; switching tabs is the `layout.switchRoot` that already exists, and because every root is already mounted and hidden with `display: none`, a hidden tab's ptys survive by construction. `tasks` names its group `task:<id>`, which is also tab 1's root id. Nothing in the kernel learns what a task is (ADR 0031).

**Tech Stack:** TypeScript (node type-stripping — **no parameter properties, no enums**), Electron, React 19, vitest, pnpm workspaces.

## Global Constraints

- **Every command runs from `v2/` and takes `env -u NODE_OPTIONS`.** An ambient `NODE_OPTIONS` makes Electron exit 9 before any of our code runs; the symptom is every check failing at once with no output explaining why.
- The full gate is `env -u NODE_OPTIONS pnpm typecheck && env -u NODE_OPTIONS pnpm lint && env -u NODE_OPTIONS pnpm test`.
- **A green unit suite is not a working app.** `env -u NODE_OPTIONS pnpm smoke:m3` must pass before any task/layout work is called done — Task 11 extends it, and it is the gate for this plan.
- `v2/tooling/eslint/boundaries.js` **is** the architecture diagram. If an import is refused, widen the rule deliberately with the reason in the rule's own comment, or find another seam. Do not widen it quietly.
- **An extension never names a vendor**, and never reads a value that would tell it which agent kind it hired.
- **`@shepherd/ui` is the design system; do not hand-roll a control.** A component paints in ROLE tokens (`--sh-accent`), never a hue.
- **Answers from `commands.invoke` are `unknown`, and a cast is not a check.** Read them defensively — they crossed an IPC port and came from code this package has never seen.
- Spec: `docs/superpowers/specs/2026-08-11-task-tabs-design.md`.

```ts
  /**
   * Which pane group this root is a TAB OF.
   *
   * Defaults to the root's own id, so a root nobody grouped is a group of one
   * and behaves exactly as it did before groups existed — that default is what
   * makes this additive rather than a migration.
```

```ts
  groupOf(root: RootID): string | undefined {
    return this.#roots.get(root)?.group;
  }

  /**
   * The roots of one group, in creation order — which IS tab order.
   *
   * Insertion order of `#roots` rather than an explicit index: a `Map` keeps it,
   * `#restore` re-inserts in persisted order, and an order field with no
   * reordering gesture to write it would be a second fact nobody maintains.
   */
  rootsInGroup(group: string): readonly RootID[] {
    return [...this.#roots.values()].filter((state) => state.group === group).map((state) => state.id);
  }
```

- [ ] **Step 3: Implement**

```ts
  /**
   * Another tab of `group`, minted with one pane.
   *
   * The id is READABLE (`task:t1/tab-2`) rather than random, because it shows up
   * in `daemon.log`, in the persisted payload and in `shepherd raw
   * layout.listRoots` — and a random id there tells you nothing about which task
   * it belongs to.
   *
   * The smallest unused N, checked against LIVE and PERSISTED roots both. Live
   * alone is not enough: a persisted root is opened lazily by the shell, so a
   * tab minted before its sibling was opened would take an id that is about to
   * be restored — and `open` is idempotent, so the collision would not throw. It
   * would silently hand the new tab the old tab's panes.
   */
  newTab(group: string, init: PaneSeed = {}): Result<RootID, string> {
    if (group === '') return err('a tab needs a group');
    const taken = new Set<string>([
      ...[...this.#roots.keys()],
      ...this.persistedRoots(),
    ]);
    let n = 2;
    while (taken.has(`${group}/tab-${n}`)) n += 1;
    const id = `${group}/tab-${n}`;
    this.open(id, init, { group });
    return ok(rootId(id));
  }
```

```ts
    registry.register(LAYOUT_COMMANDS.newTab, {
      title: 'New Tab',
      permission: 'layout',
      schema: s.object({
        group: s.optional(s.string()),
        cwd: s.optional(s.string()),
        initialCommand: s.optional(s.string()),
      }),
      /**
       * Another tab of the group you are looking at.
       *
       * Both defaults are the same idea one level apart: an unqualified gesture
       * means "here". The group defaults to the ACTIVE root's, and the cwd to
       * the pane you were looking at — which is what makes ⌘⇧T inside a task
       * land in that task's worktree without the kernel knowing what a worktree
       * is.
       */
      handler: (args) => {
        const from = resolveRoot(undefined);
        const group = args.group ?? store.groupOf(from) ?? from;
        const inheritedCwd = (() => {
          if (args.cwd !== undefined) return args.cwd;
          const pane = store.focused(from);
          return pane === null ? undefined : (store.pane(pane)?.cwd ?? undefined);
        })();
        const root = unwrap(
          store.newTab(group, {
            ...(inheritedCwd === undefined ? {} : { cwd: inheritedCwd }),
            ...(args.initialCommand === undefined ? {} : { initialCommand: args.initialCommand }),
          }),
        );
        // And land you in it: a tab you have to go and find is a tab the gesture
        // did not finish making.
        onSwitchRoot(root);
        return { root, pane: store.focused(root) };
      },
    }),

    registry.register(LAYOUT_COMMANDS.closeGroup, {
      title: 'Close Tab Group',
      permission: 'layout',
      schema: s.object({ group: s.string() }),
      /**
       * Every tab of a group, closed — what finishing with a task means.
       *
       * Each pane goes through `store.close`, which is the ONE terminator (ADR
       * 0022) and the only thing that kills a pty. Dropping the roots without
       * draining them would leak a live session per pane with nothing left
       * pointing at it.
       */
      handler: (args) => {
        const roots = store.rootsInGroup(args.group);
        if (roots.length === 0) return unwrap(fail(`no group ${args.group}`));
        let closedPanes = 0;
        for (const root of roots) {
          if (root === homeRoot) continue; // the window always has somewhere to fall back to
          for (const pane of store.panes(root)) {
            unwrap(store.close(pane));
            closedPanes += 1;
          }
          unwrap(store.removeRoot(root));
        }
        if (roots.includes(activeRoot())) onSwitchRoot(homeRoot);
        return { group: args.group, closedRoots: roots.length, closedPanes };
      },
    }),

    registry.register(LAYOUT_COMMANDS.listRoots, {
      // No title: not a palette verb. It is the read an extension makes because
      // `LayoutAPI`'s synchronous getters cannot cross a port.
      permission: 'layout',
      schema: s.object({ group: s.optional(s.string()) }),
      handler: (args) => {
        const roots = args.group === undefined ? store.roots() : store.rootsInGroup(args.group);
        return roots.map((root) => {
          const pane = store.focused(root);
          const found = pane === null ? null : store.pane(pane);
          return {
            root: String(root),
            group: store.groupOf(root) ?? String(root),
            // ONE label, resolved here — `displayTitle` is what the sidebar and
            // the tab strip both show, and computing it twice in two packages is
            // the hand-synced pair this codebase keeps getting bitten by.
            label: found === null ? '' : displayTitle(found, ''),
            focusedPane: pane === null ? null : String(pane),
            focusedSession: pane === null ? null : (store.sessionFor(pane) ?? null),
          };
        });
      },
    }),
```

### Task 4: Closing a tab falls through to its sibling, and only an empty group is "finished"

**Files:**

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces: the bus payload `{ root: string; group: string; groupEmpty: boolean }` on topic `layout.rootClosed`.

**Why this task exists:** `tasks` archives a task when it sees `layout.rootClosed` for `task:<id>`. With tabs, closing the last pane of tab 1 while tab 2 still runs an agent would archive a live task. `groupEmpty` is what stops that, and it is the sharpest correctness edge in the whole change.

```ts
  /**
   * The tab each group was last showing.
   *
   * Transient and in main, where `active` already lives, because it is a
   * property of the WINDOW — the store holds N pane groups and has no opinion
   * about which one anybody is looking at. Switching to a group's anchor means
   * "take me back to this task", and every tabbed application in existence reads
   * it that way; landing on tab 1 instead loses the tab you were working in
   * every time you glance at something else.
   */
  const lastInGroup = new Map<string, RootID>();

  const setActive = (root: RootID): void => {
    /*
     * A root whose id IS its group is that group's anchor, and asking for the
     * anchor is asking for the group. Any other root is a specific tab and is
     * honoured exactly — that is what makes the tab strip's own clicks work.
     */
    const remembered = store.groupOf(root) === String(root) ? lastInGroup.get(String(root)) : undefined;
    const target = remembered !== undefined && store.hasRoot(remembered) ? remembered : root;
    if (target === active) return;
    active = target;
    const group = store.groupOf(target);
    if (group !== undefined) lastInGroup.set(group, target);
    onActiveChanged?.(target);
    publish();
  };
```

```tsx
import { cn } from './cn.ts';
import { IconButton } from './icon-button.tsx';

/**
 * The tabs of one pane group.
 *
 * A primitive rather than markup in the shell, for the reason every control here
 * is one: the app's own tab strip and any contributed one must be the same
 * object, and a hand-rolled strip is where a hue gets typed in instead of a role
 * token. It paints in `--sh-accent` and friends and knows nothing about roots,
 * tasks or commands — it is given labels and hands back an id.
 *
 * `role="tablist"` and real `aria-selected` because the thing this replaces is a
 * row of divs: a tab a screen reader cannot report as selected is a tab whose
 * only state is a colour.
 */
export interface TabDescriptor {
  readonly id: string;
  readonly label: string;
}

export interface TabStripProps {
  readonly tabs: readonly TabDescriptor[];
  readonly activeId: string;
  readonly onSelect: (id: string) => void;
  /** Absent = no new-tab control. A strip with nowhere to send it must not draw one. */
  readonly onNew?: () => void;
  readonly newLabel?: string;
}

export function TabStrip({ tabs, activeId, onSelect, onNew, newLabel = 'New tab' }: TabStripProps) {
  return (
    <div className="sh-tabs" role="tablist" data-testid="tab-strip">
      {tabs.map((tab) => (
        <button
          key={tab.id}
          type="button"
          role="tab"
          className={cn('sh-tab')}
          aria-selected={tab.id === activeId}
          data-active={tab.id === activeId}
          onClick={() => onSelect(tab.id)}
        >
          <span className="sh-tab-label">{tab.label}</span>
        </button>
      ))}
      {onNew === undefined ? null : (
        <IconButton icon="plus" size="sm" label={newLabel} className="sh-tab-new" onClick={onNew} />
      )}
    </div>
  );
}
```

```ts
/**
 * A task's tabs → the rows its sidebar entry shows.
 *
 * **Capped at three**, and the cap is the whole reason this is a function: a
 * task with eight tabs would otherwise push every other task off the screen, and
 * the sidebar's job is the list of tasks. Past three it shows two and says how
 * many it is not showing, which is a count you can act on rather than a list you
 * have to scroll.
 *
 * **Drawn identically for one tab.** The shape of a task's entry does not change
 * as tabs are added — one tab is one row, not a special case that turns into a
 * list later.
 *
 * Pure, total, no host: the same shape as `agent-rollup.ts` beside it, and
 * testable without a layout, a store or a running app.
 */
export const TAB_ROW_CAP = 3;

export interface TabRow {
  readonly root: string;
  readonly label: string;
  /**
   * The rollup over the panes in THIS root — the state itself, not the tint it
   * is drawn as. Ranking on the state keeps this function from having to know
   * how a state is spelled for the renderer (`needsCheck` → `needs-check`),
   * which is `tintFor`'s business and changes on its own schedule.
   */
  readonly state: TaskAgentState;
}

export type CappedRow = TabRow | { readonly kind: 'more'; readonly count: number } | { readonly kind: 'less' };

export function capTabRows(tabs: readonly TabRow[], expanded: boolean): readonly CappedRow[] {
  if (tabs.length <= TAB_ROW_CAP) return [...tabs];
  // Expanded shows all of them, in creation order, plus the way back. Without
  // the `less` row the expansion would be one-way, and a sidebar you can only
  // make taller is a sidebar that ends up all one task. It does NOT promote:
  // a full list has no room problem, and one that reshuffled itself as agents
  // finished would be unreadable.
  if (expanded) return [...tabs, { kind: 'less' }];

  /*
   * Which two survive the cap: the two that WANT YOU.
   *
   * A finished agent, or a command that completed while you were looking
   * somewhere else, is the row worth having — and a cap that kept tabs 1 and 2
   * would hide exactly what the sidebar exists to surface. Loudest first by
   * `ROLLUP_PRIORITY`, creation order as the tie-break so a quiet task still
   * reads top to bottom and only a loud one reorders.
   */
  const loudness = (row: TabRow): number => {
    const index = ROLLUP_PRIORITY.indexOf(row.state);
    return index === -1 ? ROLLUP_PRIORITY.length : index;
  };
  const shown = tabs
    .map((row, index) => ({ row, index }))
    .sort((a, b) => loudness(a.row) - loudness(b.row) || a.index - b.index)
    .slice(0, TAB_ROW_CAP - 1)
    .map((entry) => entry.row);
  return [...shown, { kind: 'more', count: tabs.length - shown.length }];
}
```

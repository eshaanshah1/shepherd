## Two things that will bite you in the first five minutes

- **`env -u NODE_OPTIONS` on every command.** An ambient `NODE_OPTIONS` makes
  Electron exit **9** before running a line of our code: no window, and every
  check fails at once with nothing explaining why. `pnpm dev` and the smoke
  runners now strip it themselves; anything you invoke by hand does not.
- **`v2/tooling/eslint/boundaries.js` IS the architecture diagram.** A package may
  import something because a line there says so. Widen it deliberately, with the
  reason in the rule's own comment; widening it quietly is the drift it exists to
  prevent. Two carve-outs already exist and each says why.

Run it: `cd v2 && pnpm install && pnpm dev`. Smokes: `pnpm smoke:m1`,
`smoke:terminal`, `smoke:isolation`, `smoke:single-instance`, `smoke:session`.

### The five things worth knowing before you change any of it

1. **`layout.close` is what ends a session, and it cannot be forgotten.**
   `LayoutStore` takes a required `SessionSink`; a test asserts the converse
   (focus, rename, an observed cwd, zoom, a viewport push, a re-projection must
   never reach `kill`). ADR 0022.
2. **`isViewing` is computed in exactly one place** and threaded everywhere —
   ADR 0020's invariant, ported. Do not add a second visibility check. And
   `seen = viewing && !away`: with a shut lid, `appActive` and front-ness both stay
   true, so suppressing on `viewing` alone would kill the phone push at the one
   moment the phone exists for.
3. **One authorization path.** `authorize(caller, required, grants)` in the
   dispatcher judges the user, the kernel, an extension, a device and an agent.
   A built-in is trusted by a **write at install time**, never by an exemption
   branch — which is why `revoke` bites a built-in. ADR 0023.
4. **`Caller` has five kinds**, and `kernel` exists so core's own events are not
   attributed to `user`. No transport can mint `user` or `kernel`
   (`externalCallerSchema` has neither), and a test pins it.
5. **The viewport is pushed, not measured**, and a divider drag previews locally
   and commits **one** `layout.setRatio` on mouse-up.

### Deviations and gaps recorded during M1 (all deliberate)

- **`session_id`, not `pane_id`.** Core-design §5.2 proposed `SHEPHERD_PANE_ID`
  (= session id), which is v1's `tab_id` lie in new clothes. The spec is corrected.
- **`local-cli` is granted everything** (`main/ingress.ts`) because a 0600 socket
  in the user's own support dir *is* the authorization. It does **not** extend to a
  paired remote device or to an agent. Narrow it when pairing lands.
- **`ProcessAPI` and `SecretStore` are typed and unimplemented.** `ProcessAPI`
  lands when `tasks` needs git (M3); `secrets` returns a typed refusal.
- **`api: "^1.0.0"` ranges are shape-checked and compared against nothing.**
  An extension written for a future API fails at the call, not at load.
- **`network` has no host allowlist** (ADR 0023).
- **`onView:` activation is unimplemented** — nothing in M1/M2 declares one; it
  lands with the first real view contribution in M3.
- **`PointsAPI.get`'s "undefined if its owner is not active" holds by convention**
  (a point is a `Disposable` in `ctx.subscriptions`), not by enforcement.
- **One property nothing covers**, documented in `extensions/registry.ts`: moving
  the cycle check below the in-flight share stays green today because the
  synchronous prefix reaches the dependency loop before `pending` is assigned. It
  starts mattering the moment anyone adds an `await` ahead of that loop, and the
  failure would be a deadlock with no stack trace.
- **No permission UI**, so a third-party extension is effectively un-installable —
  which is exactly why built-ins consuming `proposed` APIs is the proving ground.
- **An extension cannot READ synchronous kernel state across the port.**
  `attention.get`/`count`, `commands.list` and every `LayoutAPI` read (including
  `isViewing`) refuse with `ACROSS_A_PORT` and say so, because `KV.get` and the
  layout reads are synchronous and a port is not. Reaching them needs a **pushed
  mirror** in the child, deliberately not built (it belongs with M3's first real
  view contribution). **If M2's `agents-core` needs `isViewing` from inside the
  child, that mirror is the work** — budget it rather than discovering it.
  Mutations are unaffected: they are commands, so an extension already reaches the
  real `LayoutStore` through `commands.invoke('layout.split')` and the one
  dispatcher.
- **`ctx.storage` is a write-through mirror**, seeded whole at activation because
  `KV.get` is synchronous. Sound only while a namespace has exactly one writer.
- **`vite@8.2.1` was NOT unpublished from npm.** `f05e5f3`'s message claims it was
  and that is false (both the version and its tarball return HTTP 200, verified).
  The hand-repaired lockfile is kept because it is a valid complete resolution
  that both install modes accept, not because the reasoning held. Don't act on the
  claim.

## Next: M2 — agents (dogfood-capable)

Per core-design §7 and **spec §7c**, which is binding:

1. **`agents-core`** — the vendor-blind agent noun. Exports `registerAgentKind`
   through **its own extension point** (so `codex`/`opencode` are third-party
   extensions, not a fork — this makes M2 the first real consumer of
   `points.define`). Owns the reconciliation sweep (state says working but
   `hasForegroundProcess()` is false ⇒ demote, log why) and is the **only** writer
   of attention for agent sessions. Exports `complete`/`stream` with a
   **normalized** event union plus a `raw` passthrough, and per-kind declared
   capabilities so asking for streaming a vendor lacks is a typed error, not a hang.
2. **`claude-code`** — injects `SHEPHERD_SESSION_ID` + `SHEPHERD_SOCK` via
   `sessions.onWillCreate`; ports **`StopPolicy.applyEvent` tests-first** with
   `viewing` threaded as a parameter; splits `ownerSessionID`/`resumeSessionID`;
   ships `report.sh` with the transport swapped to `curl --unix-socket` and one
   `jq -cn` envelope carrying a per-session `seq`.
3. Then **M3 — tasks** (SQLite task store, `TaskRootSynth`, worktree-per-repo, the
   ⌘T composer, Scratch, spawn/archive/restore, the sidebar tree, the skill + CLI
   verbs). **Dogfooding begins at M3.** Then **M4**, a week of v2-inside-v2, which
   is the gate. Workbench is first after M4.

Process that worked, twice: plan file → one feasibility review + one advisor pass
(no code) → small phases, each committed green with an explicit `deviation:` field
→ subagents for phases whose file sets do not overlap, with the orchestrator
keeping barrel wiring, integration and verification. **Verify subagent claims
yourself** — one agent died mid-report having done correct work, and a green
report is not a green tree.

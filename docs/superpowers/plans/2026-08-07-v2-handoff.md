## M1 in progress — [`2026-08-07-v2-m1-plan.md`](2026-08-07-v2-m1-plan.md)

Scope confirmed **full M1 as specced** (utility-process extension host and the
permission model included). Master was fast-forwarded to M0 first, as decided.
Two probes ran against the real Electron 43.3.0 binary before the plan was
written and both changed it: **`node:sqlite` exists** (so no native dep, no ABI
rebuild — this retires `better-sqlite3` from core-design §5.3) and
`utilityProcess.fork` is available.

The plan was reviewed by a Fable feasibility pass **and** the advisor before any
code; six decisions came out of that and are written into the plan rather than
left to the executor — P4 splits in two, a layout leaf carries its `SessionID`
(so `layout.close` ends the session and a control-socket close cannot leak a
pty), the viewport rect is pushed from the renderer rather than measured, a
divider drag previews locally and commits once, layout writes are debounced,
and there is no permission prompt to build (§7b decided grant-once).

Done, each committed green:
- `90053ba` — smoke runners strip `NODE_OPTIONS` (Electron refuses to boot on a
  flag it disallows there and exits 9 before any of our code runs).
- `c93dfaf` — the M1 plan.
- `2cfbc60` P0 — `@shepherd/sdk` grows into the core-design §4 surface under
  `api.proposed`; `Schema` (rejects unknown keys, reports every bad field,
  paths read `repos[1].path`) and `Logger` (v1's rule + the ms stamp).
  **Also decided here: spec §7c — the SDK ships batteries for agents**
  (`agents-core` exports complete/stream over `claude -p`, kernel stays
  vendor-blind, `agents` is its own permission, cross-extension calls resolve
  only declared `dependencies`).
- `18bfbbf` P1 — `CommandRegistry` (nothing throws at invoke; authorization
  before schema so a denial cannot leak argument shape; duplicate registration
  throws) + `EventBus` (per-source seq; a gap is logged and **delivered**, a
  duplicate logged and **dropped**).
- `37ccb6f` P2 — `SqliteStore` over `node:sqlite`, versioned by
  `PRAGMA user_version`, namespaced `KV` that reads-as-absent on a schema
  mismatch, plus `debounce` with `flush`.

- `0cb859f` P3 — both ingresses, HTTP over a unix socket. Closes v1's worst
  channel (a blocking 8KB `read()` on the accept thread; the observer stalled
  the observed) with tests for both failures. `control.sock` owns no verbs;
  `wait` is an NDJSON subscription. Stale-socket reclaim is a connect probe that
  refuses a live path and fails closed on anything it cannot explain.
  **Deviation recorded**: the wire field is `session_id` and the env var will be
  `SHEPHERD_SESSION_ID` — core-design §5.2's `SHEPHERD_PANE_ID` (= session id)
  is v1's `tab_id` lie in new clothes; the spec is corrected.
- `a0bb3cc` P4a **(core half)** — `LayoutStore` owns the tree, holds the
  pane→session map, and takes a **required** `SessionSink` so `layout.close`
  cannot fail to end a session. Viewport pushed not measured; persistence
  debounced with `flush`; restore mints fresh pane ids; every mutation is a
  `layout` -permissioned command with the ⌘W fall-through in one place.

389 tests (M0 ended at 220), `pnpm typecheck` and `pnpm lint` clean.

**Next: P4a's second half — the renderer rewire.** The core store is in but
*nothing imports it yet*, so the app is unchanged and consistent (the renderer
still owns its own tree via `renderer/commands.ts`). Remaining:
- new IPC: get the projection, subscribe to `layout:changed`, invoke a command,
  push the viewport rect on resize;
- `main/index.ts` builds the store + registry + `registerLayoutCommands`, with
  `SessionHost` as the `SessionSink` and `onLastPaneClosed` closing the window;
- the menu dispatches `commands.invoke` with `caller: {kind:'user'}` instead of
  sending `app:command`;
- `renderer/app.tsx` renders main's projection rather than local state, and
  `SplitView`'s recursion gets **pane-id React keys** (it is positional today,
  and once every mutation arrives as a fresh tree a leaf→split reshape would
  remount `TerminalPane` and churn xterm);
- `renderer/commands.ts` and its test retire; `app.test.tsx` /
  `split-view.test.tsx` / `pane-sessions.test.ts` get rewritten against the
  projection.

Then P4b (attention + `isViewing` + the pure routing `decide()`), P5 (extension

## Two things that will bite you in the first five minutes

- **`env -u NODE_OPTIONS` on every command.** An ambient `NODE_OPTIONS` makes
  Electron exit **9** before running a line of our code: no window, and every
  check fails at once with nothing explaining why. `pnpm dev` and the smoke
  runners strip it themselves; anything you invoke by hand does not.
- **`v2/tooling/eslint/boundaries.js` IS the architecture diagram.** A package may
  import something because a line there says so. Widen it deliberately, with the
  reason in the rule's own comment.

### The five things worth knowing before you change any of it

1. **`agents-core` is the only writer of attention for agent sessions**, and it is
   enforced by the *manifest*: it is the only one in the repo declaring the
   `attention` permission, so the dispatcher refuses anybody else. ADR 0026.
2. **Agent state and attention are two channels.** `AttentionLevel` has no
   `working`. One mapping (`attentionFor`) between them, and the alert level
   **rides the event** rather than being read back — the emit and the
   `attention.set` are two ordered crossings of one port, so a consumer reading
   the store on receipt sees the world from before the change. This bug was
   measured twice (the badge read 0; the router would have routed staleness).
3. **`viewing` reaches the child as a pushed boolean**, seeded by `sessions.list`
   (which carries `viewing` per row) and kept current by `session.viewing`. It is
   a cache of the one answer, never a second check — nothing in the extension host
   can see focus, zoom or an overlay, which is what makes it safe.
4. **The sweep fails toward NOT demoting.** `hasForegroundProcess` is tri-state;
   `undefined` means the tty could not be read and is not evidence. ADR 0028 has
   the four measured constraints — read it before touching the sweep.
5. **A vendor kind never gets a privileged path.** `claude-code` registers through
   `agents.kinds` like any third party would, and its adapter is ~60 lines. If a
   second vendor needs more than that, `agents-core` has stopped being
   vendor-blind.

### Deviations recorded during M2 (all deliberate, all flagged in the plan)

- **The §7c headless seam (`complete`/`stream`) is OUT of M2**, deviating from the
  handoff's step 4. `agents-core` has no way to spawn a process at all
  (`boundaries.js` denies `child_process`/`node-pty` in the extension host,
  `ProcessAPI` is M3), and a child→host call has a **15s** deadline against a
  `claude -p` that runs minutes — so it needs a job protocol, not a verb.
  **Earliest honest landing: M3**, where `ProcessAPI` gives it a vehicle and
  `tasks` gives it a consumer. §7c's *shape* is untouched.
- **The hook envelope carries no `seq`** (deviates from core-design §4.4/§5.2) and
  **no `jq`** (deviates from the handoff). ADR 0027 — the first was a silent
  event-drop, the second was solving a problem this design deleted.
- **The kernel injects the correlation env, not `claude-code`** (deviates from
  §5.2). ADR 0025.
- **Main relays one bus topic to the renderer by an allow-list it owns.** The
  renderer may not name a topic — `claude.hook` carries whole hook payloads on the
  same bus. This table is what M3's declarative view contributions replace.
- **Resume is half a feature, and the half is named.** `resumeSessionID` is
  captured in the kind's slot and readable via `claudeCode.resumeTarget`; nothing
  persists it across a restart because layout persistence is deliberately unwired.
  The consumer lands with that, in M3.

### Gaps and follow-ups, honestly

- **No real-`claude` run has happened yet.** `smoke:m2` drives a *stub* agent over
  the real wire, which proves the chain; it does not prove Claude Code's actual
  payloads match what `claude-code` reads. **This is the first thing to do in M3**
  and it needs a human: `pnpm dev`, install the plugin at
  `~/.claude/skills/shepherd-v2`, type `claude` in a pane, watch the indicator,
  then blur the window and watch for the badge + one notification.
- **The plugin has no installer yet.** P4 shipped the plugin directory; the
  create-or-repair install command (ADR 0005's five-case classification) is not
  built. Symlink it by hand until then.
- `s.object` rejects unknown keys, which is right for a command's *arguments* and
  wrong for its *answer*. `agents-core` hand-rolls a lenient reader
  (`readSessionRows`). **If M3 adds a second answer-consumer, that is the moment
  to give the SDK a lenient-object combinator** rather than repeat the reader.
- Layout persistence is still unwired on purpose (a restored tree would make the
  smokes non-deterministic). M3 needs it for resume.
- `onView:` activation is still unimplemented; it lands with M3's first real view
  contribution, which is also what retires the relay's allow-list.
- The sheep silhouette (Flock rule 8) is not drawn — the indicator is the
  rule-sanctioned dot + micro-label fallback. **M2 is not blocked on artwork and
  neither is M3.**

## Next: M3 — tasks

Per core-design §7 and sketch §4: the SQLite task store, `TaskRootSynth`,
worktree-per-repo, the ⌘T composer, Scratch, spawn/archive/restore, the sidebar
tree, the skill + CLI verbs. **Dogfooding begins at M3.** Then **M4**, a week of
v2-inside-v2, which is the gate.

Process that worked three times: **plan file → one feasibility review + one
advisor pass (no code) → small phases, each committed green with an explicit
`deviation:` field → ADRs at the end.** M2's review caught a blocker that reached
the user's live v1 app; its advisor pass caught a port-ordering race that unit
tests cannot see. Neither was expensive.

Two habits that paid repeatedly and are cheap to keep:

- **Probe before planning.** M1's `node:sqlite` probe deleted a native
  dependency; M2's two probes deleted a subprocess and killed a predicate that
  would have demoted every live agent while every unit test passed.
- **Mutation-test the load-bearing behaviours.** Break it on purpose and confirm a
  named test fails. It found a vacuous test *and* a wrong comment in P5 — the
  claim that a conditional React sibling remounts its neighbour, which is false.
- **Verify a subagent's claims, never its report.** Fan-out is good at breadth and
  bad at seams: in M2 the joins between three parallel slices held two real bugs
  (an unexported barrel, and a command registered nowhere at all), and neither
  agent could have seen them.

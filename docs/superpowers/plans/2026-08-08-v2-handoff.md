## Two things that will bite you in the first five minutes

- **`env -u NODE_OPTIONS` on every command.** An ambient `NODE_OPTIONS` makes
  Electron exit **9** before running a line of our code.
- **`v2/tooling/eslint/boundaries.js` IS the architecture diagram.** It caught
  two real things during M3. Widen it deliberately, with the reason in the rule's
  own comment — `boundary/extension-tests` is what that looks like.

Run it: `cd v2 && pnpm install && pnpm dev`. **Eight** smokes: `smoke`,
`smoke:session`, `smoke:terminal`, `smoke:isolation`, `smoke:single-instance`,
`smoke:m1`, `smoke:m2`, **`smoke:m3`**.

## Where things stand

**1011 tests** (M2 ended at 852; M3 at 998), typecheck + lint clean, all eight
smokes green.

**M3 is complete** under its plan's cut (P0–P5 + a reduced P7). **M3b is done
except Scratch**: P6 (the view mechanism), P6b (the task tree), and the composer
— a task is now creatable from inside the app, through a **contributed React
component** (ADR 0033), with `smoke:m3` driving the real form in the real DOM.
What exists now that did not on 2026-08-07:

- **`ProcessAPI`**, in its one legal home (`packages/platform/darwin/src/exec.ts`),
  with both v1 git bugs made structural. Plus the per-call deadline (ADR 0030).
- **Agent principals** — nothing had ever populated `grants.agents`, so every
  `caller.kind === 'agent'` invocation of every command was denied. A live agent
  principal is a live session, derived from the pty host's inventory.
- **`ctx.dataDir`** — extensions may not reach `node:os`, so the host hands each
  one a directory (`~/.shepherd/v2/tasks/<slug>/…`).
- **Layout persistence**, on. It had been built since M0 and disabled by one
  omitted option.
- **The `tasks` extension**: KV store (ADR 0032), the five verbs, its own
  `tasks.repoSuggestions` point, worktree-per-repo provisioning, `TaskRootSynth`
  (ADR 0029), and archive/restore that round-trips byte-identically.
- **The `shepherd` CLI** (`packages/cli`) — §7b's agent API.
- **The view mechanism** (ADR 0031) and a task tree drawn through it.
- **react-grab**, dev-only.
- **The `component` view kind** (ADR 0033) — §7b's in-proc React seam, built
  against `diagnostics`' card first and consumed by **the composer**: a form in
  the dock that creates a task, picks repos through the `tasks.repoSuggestions`
  point, and shows what came back. An extension's two halves are now two
  directories (`src/` service, `ui/` page) with a lint boundary between them.

## What is left, in order

1. **Scratch** (D9) — ⌘T-with-defaults as a loose shell, its own persisted list,
   cwd + title only, never a resumed agent. The seam it was waiting on exists
   now: it is another `component` view plus a store, same shape as the composer.
2. **⌘T itself.** The composer is a dock view, which is where the dock model
   puts a view. A keystroke needs either a placement vocabulary (`REGIONS` —
   ADR 0031 names it as the scope-creep door) or a menu that consumes
   `contributes.commands[].key`, which **nothing reads today**. Either is its
   own piece of work; the milestone bar ("creatable from inside the app") is met
   without it.
3. **M4 — the dogfood gate.** A week of v2 inside v2. Everything it needs exists.

## Known gaps, honestly

- **`tasks.spawn` records intent; it does not create a session yet.** The verb,
  its scoping and its authorization are real and proven; giving it a live session
  in a worktree is the next piece of `tasks`.
- **No `shepherd` shim on PATH.** The CLI runs via `node packages/cli/src/main.ts`.
  v1's `CLIShim` (create-or-repair, never replace) belongs with packaging.
- **No plugin installer.** `~/.claude/skills/shepherd-v2` is a hand-made symlink.
  ADR 0005's five-case classification is unbuilt.
- **A handler failure's message is doubled** — wrapped once in the child and
  again in main. Cosmetic, pre-existing.
- **`registerStatusItem` and panel views refuse**, naming a later milestone.
  Panel views stay the decided answer for the **app-like** case (the workbench,
  which brings its own editor) — ADR 0033 records why the composer is not one.
- **The in-proc UI table is static** (`renderer/extension-ui.ts`), so a
  third-party extension has no way to contribute a component yet. §7's
  graduation order, deliberately: a runtime loader is the next piece, not this
  seam.
- **No repo history for the picker.** The default suggestion provider answers
  with the repos of recent tasks, which is thin on a fresh install and empty on
  first run — typing a path is the primary entry, a suggestion the accelerator.
  Usage-and-recency ranking wants history nothing records yet.
- **The interactive trust dialog** for a generated `settings.json` is unmeasured
  (ADR 0029's open question). Headless, with no trust record, it is honoured.

## What M3 taught, that the next milestone should keep doing

**Three gates were passing without checking anything**, and each was found by
mutation-testing rather than by reading:

- `extensions/tasks` was missing from the root tsconfig references, so
  `pnpm typecheck` never looked at it — a planted type error produced no output.
- A deadline test used `Promise.race` against an already-resolved sentinel, which
  wins by one microtask regardless; it passed with the change reverted.
- A round-trip comparison passed with **both sides empty**, because the worktree
  had never been provisioned.

**The composer's own live run kept the streak.** Its first run failed on a
hardcoded repo name in the smoke: the CLI *supplies* a repo's name and the
picker *derives* it from the path, so the composed task's worktree is at the
path's basename, not `api/`. The component's first unit test found a second one
— a suggestion provider answering something that is not an array took the whole
form down with a `TypeError`, because a cast is not a check and a third-party
provider is exactly what D5 invites.

**Driving the real thing found what unit tests could not**: the CLI's first run
turned up a wrong route, a kernel-level disagreement about "no arguments"
(`s.nothing()` rejected `{}` while an all-optional `s.object` rejects absent, so
no generic client could speak to both), and my own fix for the first of those
breaking the second. The view mechanism's first run turned up three more.

**Probe before planning still pays.** Probe 2 ran v1's own algorithms against
fixtures and found a **silent bug in `WorktreeService`** — a branch existing only
on a remote gets the wrong content under the right name with a wrong upstream,
exit 0, first symptom a push failing much later — which a faithful port would
have carried into v2's foundation.

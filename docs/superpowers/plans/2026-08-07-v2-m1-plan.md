# v2 M1 — implementation plan (the kernel)

Goal (from [`2026-08-06-ade-v2-core-design.md`](../specs/2026-08-06-ade-v2-core-design.md) §7 M1):
extension host + manifest/permissions, command registry with attributed
callers, event bus + both HTTP-over-unix ingresses, storage, attention
aggregation, **and the app's own chrome re-expressed through the API so it
becomes caller #1**. Scope confirmed 2026-08-07: *full M1 as specced* —
utility-process extension host and the permission model included, not deferred.

Predecessor: [`2026-08-07-v2-m0-plan.md`](2026-08-07-v2-m0-plan.md) (green, 220
tests / 24 files at `25bbd2a`, now fast-forwarded onto `master`).

## Probes already run (both green, 2026-08-07)

Two design questions that would have changed the plan were settled empirically
before writing it, against the real Electron 43.3.0 binary:

- **`node:sqlite` exists in Electron 43** (Node 24.18.1): `DatabaseSync`,
  `StatementSync`, `Session`, `backup`. So the task/extension store needs **no
  native dependency and no `@electron/rebuild` against Electron's ABI** —
  `better-sqlite3` (core-design §5.3) is superseded by stdlib. This also keeps
  `packages/core`'s import boundary at "stdlib + node-pty" with no second
  exception, which the boundary lint would otherwise have to grow.
- **`utilityProcess.fork` is available**, so the §7b decision "extension
  services run in one utility process" is buildable as specced.

Recorded here because a later reader will otherwise assume the SQLite choice
drifted. Both go in an ADR at the end of M1.

## Constraints (bind the executor)

- Everything under `v2/`. The Swift app in `spike/` is reference material and is
  never touched. No `spike/` file appears in any M1 diff.
- **Import boundaries stay honest.** `packages/core` imports stdlib + node-pty +
  sdk. `node:sqlite` and `node:http` are stdlib and need no carve-out;
  `node:net` likewise. If a phase seems to need a new exception in
  `tooling/eslint/boundaries.js`, that is a design smell — stop and report
  rather than widening the rule quietly. (Widening it *deliberately*, with the
  reason in the rule's own comment, is fine; the file is the architecture
  diagram and edits to it are the audit trail.)
- **Nothing calls `Date.now()` or bare `setTimeout`** in core or an extension —
  `Clock` is injected (already in the SDK). New state machines (ingress
  timeouts, the debounced layout write, attention aggregation) get fake-timer
  tests. This is review §Bad-9, and it is the reason those tests are cheap now.
  Note there is **no permission-prompt state machine to build**: §7b decided
  review-at-install / grant-once, so built-ins are pre-granted and nothing in M1
  interrupts a first use.
- **Pure first, tests-first.** Every phase's decision logic is a pure function
  with its own test file; the IO shell around it is thin enough to read. A phase
  is done only when `pnpm -r test` and `pnpm typecheck` pass **and the test
  count moved** (baseline 220 — `pnpm test:count`).
- **`proposed.*` API gating** (sketch §7): everything M1 adds to `@shepherd/sdk`
  lands as proposed, usable only in dev-mode builds. Built-ins are *required* to
  consume proposed APIs — that is the proving ground. Mechanism: a
  `proposed: true` flag on the API descriptor plus a host-side gate keyed off
  `IS_DEV`; graduation is a later, deliberate edit.
- **Every failure is a value, never a throw, at every boundary a caller or
  extension can reach across** — the `Result` discipline `SessionHost` already
  holds. An unknown command, a failed schema, a denied permission, a wedged
  ingress body: typed error, logged, never a silent no-op (review §Bad-2).
- Commit at each phase boundary on `fable-electron-refactor`, message style
  `feat(v2): …`, project Co-Authored-By line, plus a 3-line summary and an
  explicit `deviation:` field (empty = none).

## Modules

1. **`packages/sdk` — the real API surface.** The core-design §4 interfaces as
   types, plus three pure runtime helpers extensions and core both need:
   - `Schema<T>` — a hand-rolled, zero-dependency structural validator with
     combinators (`str/num/bool/lit/enum/obj/arr/opt/union`) whose `parse`
     returns `Result<T, SchemaError>` carrying a **path** to the bad field. A
     dependency would be defensible; ~150 lines is cheaper than a version pin,
     and the command dispatcher needs the error *shape* to be ours because it
     travels over IPC and the control socket.
   - `Logger` — `logDebug/Info/Warn/Error(category, message)`. v1's rule ports
     verbatim: **every branch that ends in "and then nothing happens" logs
     why.** Millisecond timestamps (they get correlated against other logs),
     level from config, category enum. Dependency-free for the same reason v1's
     `Log.swift` was.
   - `Caller`, `Envelope`, `Permission`, `Manifest` DTOs.
2. **`packages/core/src/commands` — the one verb table.** `CommandRegistry`:
   `register(id, {schema, handler, permission?})`, `invoke(id, args, caller)`.
   Authorization runs **in the dispatcher**, before any handler, against the
   caller kind (review §Bad-3's hole, closed at the envelope). Pure
   `authorize(caller, spec, grants)` with its own tests including negative
   controls.
3. **`packages/core/src/events` — the bus.** `emit/on`, `Envelope {seq, ts,
   source}` with a **per-source** monotonic sequence so a gap is *detectable*
   (the `PreToolUse`/`PermissionRequest` race v1 could not see). Listener throw
   is isolated and reported, never dropping the rest of the fan-out.
4. **`packages/core/src/storage` — one store, versioned.** `node:sqlite`
   `DatabaseSync`; a `meta` table carrying `schemaVersion`; forward-only
   migrations as an ordered array of pure `(db) => void` steps; a namespaced
   `KV` per extension (`ctx.storage`) and a `select-by-id` discipline
   throughout. No string-literal key sprawl: a namespace is a value, not 34
   copies of a prefix (review §Bad-8).
5. **`packages/core/src/ingress` — two unix sockets, both HTTP.**
   `http.createServer` over `node:net` unix paths, so framing, ack, request
   timeout and body-size limit come for free (review §4's best-rebuild move).
   - `events.sock` — hooks POST one `jq -cn` envelope; `pane_id` named
     honestly; per-session `seq`. Reads to EOF with a cap, never one blocking
     8KB `read()`. **The observer must not be able to stall the observed.**
   - `control.sock` — the CLI: a thin adapter over `commands.invoke` with
     `caller: {kind:'device'|'agent'}`. `wait` is a long-lived NDJSON
     subscription, never 200ms polling.
   - **Stale-socket reclaim**: connect-probe first; `ECONNREFUSED` means the
     file is a corpse and may be unlinked; a successful connect means another
     live instance owns it and we must not steal it (v1's silent CLI theft).
     M0's single-instance lock already runs before this.
6. **`packages/core/src/layout` — ownership moves to main.** M0 keeps the tree
   in the renderer (`renderer/commands.ts`); M1 makes core the owner, because
   `LayoutAPI`, attention aggregation, and `isViewing` are all core per the
   design and extensions read the tree. A `LayoutStore` over the ported
   `SplitTree`: roots (one per window) → regions → split nodes; focus, zoom,
   collapse. **Every mutation is a registered command** — the one normalizing
   funnel (§Bad-10). The renderer becomes a projection plus a transport.

   Five things this move decides, each of which is already answered by v1 and so
   is **decided here, not left to the executor**:
   - **A leaf carries its session.** Core-design §4.2's `open(view, target)`
     seam: the layout node holds the `SessionID`, so `layout.close` is what ends
     the session. Without it, closing a pane over `control.sock` leaks a live
     PTY while the renderer's own close path double-kills. Today that binding
     lives in `renderer/pane-sessions.ts` and `app.tsx` calls itself "THE one
     place a session is ended" — that sentence has to stay true, one process
     over.
   - **The viewport is pushed, not measured.** `neighbor` needs a `Rect` and
     core has no DOM, so the renderer publishes each root's content rect on
     resize and core caches it — exactly what v1's `ContentView` does ("feeds
     the content rect to the store so ⌘⌥-arrow focus moves can resolve
     geometric neighbors"). Focus commands therefore take no rect argument and
     stay invokable from the CLI and from an extension.
   - **A divider drag previews locally and commits once.** `setRatio` per
     mousemove through a command registry is a 60Hz IPC storm (and, with eager
     persistence, 60Hz sqlite writes). The renderer previews; **one**
     `layout.setRatio` lands on mouseup. Also v1's behaviour.
   - **Layout persistence is debounced.** Review §Bad-8's `save()`-on-every-`cd`
     is the trap this phase would otherwise recreate at higher frequency.
   - **React keys are the pane id.** `SplitView`'s recursion is positional
     today; once every mutation arrives as a freshly deserialized tree, a
     leaf→split reshape remounts `TerminalPane` and churns xterm. The session
     survives (that is the whole M0 win) but the reattach is still visible, and
     stable keys are the review's stated remedy.
7. **`packages/core/src/attention` — one channel, aggregated.**
   `set(target, {level, reason, color?})`; roll-up per node/root; dock badge
   count; the ⌘⇧A ring order. Routing (banner / chime / push, `isViewing`
   suppression) is a **pure `decide()`** ported from v1's
   `NotificationRoutingPolicy`. `isViewing(nodeId)` is computed **once**, in
   core, from (app active, window focused, selected root, focused node, zoom
   starvation, full-takeover overlay) — ADR 0020's predicate, one place, no
   second visibility check anywhere (v1's hardest-won invariant).
8. **`packages/core/src/extensions` + `packages/app/src/main/ext-host` — the
   extension host.** Manifest parse/validate; activation events
   (`onStartup`/`onCommand:`/`onView:`); a `PermissionStore` with **grant-once**
   semantics and a pure `permissionDiff(granted, requested)` so an update that
   asks for more re-prompts and one that asks for the same does not;
   `utilityProcess.fork` running the host; typed RPC frames over `MessagePort`
   with a **negotiated protocol version** and unknown-frame = log-and-skip,
   never discard-the-batch (review §Bad-2 reincarnated in the bridge, closed
   before it opens); the `Shepherd` api proxy the host hands `activate()`; and
   `points.define/register/all/first` — the extension-point primitive, so an
   extension can be a platform too (core-design §4.7).

   Three constraints on this module:
   - **The child is a fourth build target.** `utilityProcess.fork` needs built
     JS and `electron.vite.config.ts` builds main/preload/renderer only. This
     blocks P5 on its first day if unnoticed.
   - **The child may not `import` `node:process`** — it lives under
     `app/src/main/**`, where the boundary lint denies that, and the frame port
     is the `process.parentPort` **global** anyway. Lint cannot see a global, so
     this is a note rather than a guard.
   - **A dead host says so.** An extension host that crashes or wedges takes
     every extension with it; unlogged, that is v1's `acceptBridged`
     silent-no-op reborn (review §Bad-5). Exit code logged, one bounded restart,
     and extensions marked failed rather than silently absent.

   `points` ships as the primitive **plus its own unit tests, and no artificial
   consumer** — `tasks` is the first real one (M3). Building a fake consumer to
   prove it would break this plan's own rule against building for M3.

## Phases

Each ends green, committed, with a 3-line summary and `deviation:`.

- **P0 — SDK surface + `Schema` + `Logger`.** Types for all of §4; the two pure
  runtime helpers, tests-first. `ProcessAPI` and `SecretStore` are **typed and
  not implemented** in M1 — `ProcessAPI` gets its implementation when `tasks`
  needs git (M3), `SecretStore` when something needs a credential. Saying so
  here stops an executor building a keychain this milestone.
  *(The `NODE_OPTIONS` smoke fix this phase was to carry landed early and
  separately as `90053ba`, verified against the real binary.)*
- **P1 — command registry + event bus.** Two small pure kernels, one commit.
  `authorize(caller, spec, grants)` takes grants as a **passed value**, not a
  store lookup — that is what lets it exist four phases before `PermissionStore`.
  Negative controls: unknown command, schema failure, denied caller, throwing
  handler, throwing listener, sequence gap.
- **P2 — storage.** `node:sqlite` store, `schemaVersion` + migrations, namespaced
  `KV`, tested against `:memory:` and a real temp file (the migration path only
  exists on disk). `node:sqlite` prints an `ExperimentalWarning` on import and
  the smokes parse stdout — filter it at the source rather than teaching every
  runner about it.
- **P3 — the two ingresses.** HTTP-over-unix for both, stale-socket reclaim,
  body caps, timeouts, NDJSON `wait`. Tested over real sockets in a tmpdir,
  including the two stall cases: a client that connects and writes nothing, and
  a body over the cap. **Exit criterion names its own limit**: the layout verbs
  arrive in P4 and agent state in M2, so P3's tests drive *registered test
  commands* and `wait` subscribes to bus topics — there is nothing else to
  invoke yet, and pretending otherwise would mean building M2 here.
- **P4a — layout ownership moves to core.** `LayoutStore`, the session-carrying
  leaf, mutations as commands, the pushed viewport rect, debounced persistence,
  pane-id React keys, and the renderer rewired to project main's tree. All in
  one phase because a half-moved layout is not a state anything can be tested
  in — and *only* this, because the diff is the riskiest in M1.
- **P4b — attention.** `set`/aggregation, the badge count, the ⌘⇧A ring order,
  `isViewing` as the single core predicate, and the pure routing `decide()`
  ported from v1. Aggregation and badge get **wired**; banner/chime/push have no
  producer until M2's agents, so `decide()` lands tested but unplugged.
- **P5 — extension host.** Manifests, permissions (grant-once + pure diff),
  `utilityProcess` + typed RPC + the fourth build target + liveness, and
  `points`. Proven by **one built-in**: it activates, registers a command that
  invokes through the real registry, and gets a typed error — not a crash — for
  a capability it never declared.
- **P6 — chrome as caller #1 + the M1 smoke + ADRs.** Every ⌘-key and menu item
  in the app becomes `commands.invoke` with `caller: {kind:'user'}`. One real
  Electron smoke drives the kernel end to end: boot → `curl --unix-socket
  events.sock` posts an envelope and the bus shows it **with its sequence** →
  `control.sock` invokes a layout split and the window shows two panes → a
  command sets attention and the badge reflects it. Note the shape of that
  third leg: nothing maps *ingress events* to attention until M2's
  `agents-core`, so asserting "curl → badge" here would fail by design.
  ADRs for the SQLite substitution, layout ownership moving to main, and the
  permission model.

## One thing the SDK types must not imply

§7b decided **two different things** about extension code: *services* run in the
utility process, and *UI* is in-proc React. M1 does not have to reconcile them —
every view contribution M1, M2 and M3 need is **declarative** (`tree` rows,
status items, glyphs), which crosses RPC as data. But the P0 typings must not
describe a React component travelling over a message port, because that corner
is expensive to unpaint later. A `ViewProvider` in M1 returns data; the in-proc
React seam is a later, deliberate addition.

## Out of scope for M1

`agents-core`, `claude-code`, `StopPolicy` (M2). Tasks, worktrees,
`TaskRootSynth`, the composer (M3). Workbench, remote, nudges, onboarding,
packaging/signing, the sheep artwork, Playwright. `ProcessAPI`/`SecretStore`
implementations, and the `onView:` activation event (nothing in M1 or M2
declares one — it lands with the first real view contribution, in M3).
Resist all of them — the temptation in P4 is to build the sidebar the task list
will need; the sidebar is an extension view and it is M3's.

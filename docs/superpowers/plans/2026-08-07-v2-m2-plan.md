# v2 M2 — implementation plan (agents)

Goal (from [`2026-08-06-ade-v2-core-design.md`](../specs/2026-08-06-ade-v2-core-design.md) §7 M2,
as reshaped by sketch **§7c**, which is binding and post-dates §5.1):
`agents-core` + `claude-code` live, `StopPolicy` ported tests-first, the plugin
transport swapped, badge/notifications, the reconciliation sweep.

**The exit, concretely:** a real `claude` running in a v2 pane drives a real state
indicator. Its hooks reach the app over `hooks.sock`, the ported `StopPolicy`
reduces them, attention aggregates, and the dock badge and a notification follow.

Predecessor: [`2026-08-07-v2-m1-plan.md`](2026-08-07-v2-m1-plan.md) (green at
`fd5910a`, 699 tests, all five smokes). Branch: `v2-m2-agents`, off `master`.

## Probe already run (green, 2026-08-07)

One design question that would have changed the plan, settled empirically before
writing it — the same habit that retired `better-sqlite3` in M1.

- **`node-pty`'s `IPty.process` reports the pty's FOREGROUND process on macOS.**
  Measured against a real pty: an idle `zsh` reads `"zsh"`, `sleep 4` running in
  it reads `"sleep"`, and it returns to `"zsh"` when the sleep ends. So review
  §Bad-5's reconciliation sweep — *state says working but nothing is running* —
  needs **no subprocess and no `ProcessAPI`**, which is M3. Without this probe the
  sweep's only input would have been a `ps` shell-out, and `ProcessAPI` would have
  been dragged a milestone forward to serve one boolean.

Recorded here so a later reader does not assume the sweep's input drifted. It goes
in an ADR at the end of M2.

## Decisions taken here, not left to the executor

Nine, each because the alternative is a half-built seam nobody can test in.
Numbers 1, 2 and 9 are **deviations from a written spec** and are flagged as such;
the rest resolve gaps the specs left open.

### D1 — the kernel injects the correlation env, not `claude-code`

**Deviates from core-design §5.2 and the handoff's step 5**, both of which give
env injection to `claude-code` via `sessions.onWillCreate`.

It cannot be built that way. `SessionHost.onWillCreate` is **synchronous by
documented design** (`session/host.ts`: "`create` returns a `SessionID` that the
layout needs in the same tick; an async hook would make session creation a promise
and every caller a state machine"), and an extension runs in a utility process — a
synchronous callback cannot cross a port. The file already names the escape hatch:
*"a hook that needs IO does it at registration time and closes over the answer."*

Both values are kernel facts anyway. `SHEPHERD_SESSION_ID` is core's own declared
correlation key ("THE correlation key, everywhere"), and the events socket is
core's own front door. **v1 agrees**: the *app* injected the env per pane and the
plugin only ever read it. So `main/index.ts` registers one in-process
`onWillCreate` hook and every session gets the correlation env, whether or not any
agent extension is loaded.

What `claude-code` still owns, which is the substance of §5.2: the plugin
(`hooks.json` + `report.sh`), the `claude.hook` subscriber, `StopPolicy`, and
resume. It loses only the part that was never vendor-specific.

`sessions.onWillCreate` stays typed in the SDK and keeps refusing across the port
— with its reason corrected from `LANDS_IN('M2')` to the synchronous-callback one,
because "it arrives in M2" will be false the moment this lands and a stale refusal
is worse than an honest one.

### D2 — `viewing` reaches the child as one pushed boolean per session

The handoff offers two options — build a pushed mirror, or thread `viewing` into
the event payload the child already receives. **Take the mirror, at its minimum
size**, because the second option cannot serve the case that actually bites.

Threading per event covers `StopPolicy`'s landing (a `Stop` under your eyes lands
`idle`, ADR 0020). It does **not** cover the other half of v1's table: *looking at
a pane clears need-to-check*. That is an edge with no hook event behind it, so
there is nothing to thread it onto — and a poll for it would be v1's bug exactly
(`didFocus` only fired on a focus *change*).

So: `ViewingResolver` — still the one and only predicate — publishes every edge as
a bus topic, `session.viewing` `{sessionId, paneId, viewing}`, emitted only for
panes bound to a session. `agents-core` keeps a `Set<SessionID>` fed by it and:

- passes `viewing: viewed.has(id)` into the kind's state machine, and
- on a `false → true` edge, re-lands `needsCheck → idle` for that session.

This is a **cache of the one answer, not a second check** — nothing in the child
recomputes front-ness from focus, zoom or overlay, which is what ADR 0020
forbids. No layout tree crosses the port, and no protocol frame changes.

### D3 — `points` move to the SDK and run in the child

`registerAgentKind` carries `detect`, `stateMachine`, and (§7c) `headless.argv` /
`headless.parse` — all **functions**, which cannot cross a port. They do not have
to: §7b puts every extension service in **one** utility process, so `agents-core`
and `claude-code` share an address space and an in-process point registry is the
correct implementation rather than a compromise.

`boundaries.js` denies `@shepherd/core` in `app/src/ext-host/**`, and that denial
is right (a core import there would be a second, empty kernel). Core's
`PointRegistry` is pure, zero-dependency, and has **no consumers in core** — so it
relocates to `packages/sdk`, which is where core-design §4.7 puts it anyway ("the
SDK ships a standard extension-point primitive"). Core re-exports it so nothing
outside moves.

Two rules keep §7c honest, both enforceable in the child:
- `define` records its owner; a second `define` of the same id is a typed refusal,
  not a silent second registry.
- `get(id)` resolves only if the caller **declared the point's owner** in its
  manifest `dependencies`. The `activate` ask already carries the manifest, so the
  child has what it needs. Declared, not discovered (§7c).

### D4 — an extension may export an API, and `extensions.get` becomes real

`claude-code` must reach `agents-core`. Today `activate` returns `void` and
`ExtensionsAPI` refuses with `ACROSS_A_PORT` — which stops being true under D3:
both extensions are in *this* process.

`ActivateFn` gains a return value (`void | T | Promise<void | T>`); the child
runtime records it per extension; `extensions.get<T>(id)` resolves it, gated on
the same declared-`dependencies` check as D3, and `isActive(id)` answers from the
same table. Activation **ordering is already correct** —
`ExtensionRegistry.#run` activates `manifest.dependencies` first, and its cycle
check is the documented landmine, so nothing is added there.

The refusal that remains, and must be written into the code: an extension in a
*different* process still cannot be reached this way. Nothing is, today.

### D5 — `hasForegroundProcess` is a kernel command; the sweep asks the *kind*

`SessionHost` gains `foregroundProcess(id): string | undefined` over the probed
`IPty.process`, and a `sessions.list` command (permission `sessions`) answers
`{id, cwd, command, foregroundProcess, cols, rows, paneId}` per live session.

The naive predicate — *foreground differs from the session's own command* — is
**wrong for a session whose command IS the agent** (a headless `claude` reads as
idle while it is alive, and the sweep would demote a living agent). So the
predicate is the kind's:

```ts
detect({ foregroundProcess, command }): boolean   // "is this session running my vendor?"
```

The sweep demotes only when the state says `working`/`blocked`, the session is
still live, `detect` is false, **and** `detect` was not already true of the
session's own command. A direct-command session's liveness is `onDidExit`, which
is exact and needs no sweep at all.

One predicate, two jobs: the same `detect` is how a plain shell that has just
started `claude` becomes a tracked agent.

### D6 — agent state and attention are two channels, and only one of them alerts

`AttentionLevel` is `none | info | attention | urgent`. It has no `working` and no
`idle`, so **attention cannot drive the indicator** — Flock rule 8's five states
(standing / walking / grazing / butting the fence / tipped over) are *agent*
states. Conflating them would put `working` on the dock badge.

- `agents-core` owns `AgentState` (`shell | idle | working | blocked | needsCheck
  | error`, ported from v1) and publishes `agents.stateChanged`
  `{sessionId, state, reason?, turnFinished}` on the bus.
- It maps that onto attention, and this mapping is the **only** place agent state
  becomes an alert: `needsCheck → attention`, `blocked | error → urgent`,
  everything else → clear. Core's `AttentionStore` already clears `attention` (and
  deliberately not `urgent`) when a pane is viewed, so v1's table survives with no
  second implementation.
- `turnFinished` rides the state event, never `state === needsCheck` — the viewing
  landing makes the latter miss (ADR 0020, and CLAUDE.md says so twice).

`decide()` currently has **zero callers**; M2 is where it gets plugged in, in
main: banner/chime from the agent-state event (which is the only thing that knows
`turnFinished`), badge count from `attention.count()` via `onDidChange`.

### D7 — only `agents-core` may hold the `attention` permission

The handoff's "`agents-core` is the ONLY writer of attention for agent sessions"
is currently a rule held by discipline. Make it hold by construction:
`claude-code`'s manifest declares `sessions` and **not** `attention`, and its
transitions reach attention only by returning them from its registered kind.
The one authorizer in the dispatcher then enforces the invariant, and a future
kind that tries to write attention directly gets a typed `denied` rather than a
code review.

### D8 — two id spaces, named apart

Shepherd's `SessionID` (the pty, the value of `SHEPHERD_SESSION_ID`, the
envelope's `session_id`) and **Claude's** `session_id` inside a hook payload are
different things, and v1 conflated names around them.

- `sessionEventAccepted(sid, owner)` ports verbatim from `StopPolicy.swift`. The
  bug it kills is live in v2: a nested `claude -p` run via Bash inherits the
  parent's env and fires hooks tagged with the parent's `SessionID` but carrying
  its own Claude `session_id`.
- Per review §Ugly-4, the one field splits in two: **`ownerClaudeSessionID`** (the
  ownership lock, taken on `SessionStart`, released on `SessionEnd`) and
  **`resumeSessionID`** (the `--resume` target). v1 held them apart with a
  side-effecting clear in an unrelated function.

### D9 — the env vars are `SHEPHERD_EVENTS_SOCK` and `SHEPHERD_CONTROL_SOCK`

**Deviates from `events-ingress.ts`'s doc comment**, which writes `SHEPHERD_SOCK`
(as does v1). Two reasons, and the second is not theoretical:

- v2 has **two** sockets. `SHEPHERD_SOCK` names neither of them.
- **v1 is the user's daily driver on this machine and its plugin is installed
  globally.** v1's `report.sh` reads `SHEPHERD_SOCK` and pipes to `nc -U`; v2's
  reads it and speaks HTTP over `curl --unix-socket`. Same variable, two
  incompatible protocols, one machine. Today they cannot collide (each app injects
  only into its own ptys, and v1's hook exits early without `SHEPHERD_TAB_ID`) —
  but that safety rests on a guard in a file we are replacing, which is exactly
  the kind of load-bearing accident this project writes ADRs about.

Coexistence is then explicit and checkable: **different env var, different plugin
directory** (`~/.claude/skills/shepherd-v2`), so a `claude` in a v1 pane fires
v1's hooks and no-ops v2's, and the reverse. The ingress doc comment is corrected
in the same commit that introduces the variable.

## Constraints (bind the executor)

- Everything under `v2/`. The Swift app in `spike/` is **reference material and is
  never edited** — no `spike/` file appears in any M2 diff.
- **`env -u NODE_OPTIONS` on every hand-run command.** An ambient `NODE_OPTIONS`
  makes Electron exit 9 before running a line of our code, and the symptom is
  every check failing at once with nothing explaining why.
- **`tooling/eslint/boundaries.js` IS the architecture diagram.** `extensions/**`
  may import `@shepherd/sdk` and nothing else — which is the point, since a
  built-in reaching into the kernel would stop being proof the public API
  suffices. If a phase seems to need a new exception, **stop and report** rather
  than widening it quietly. D3 is deliberately arranged to need none.
- **`erasableSyntaxOnly` is on**: no enums, no namespaces, **no constructor
  parameter properties**. Electron type-strips the main entry, so those are a
  *launch* failure a passing test suite will not catch.
- **Nothing calls `Date.now()` or a bare `setTimeout`.** `Clock` is injected. The
  reconciliation sweep is a timer machine (review §Bad-9's class) and gets
  fake-timer tests — that is the whole reason it is cheap to write here.
- **Every failure is a value at every boundary a caller can reach across.** Typed
  error, logged, never a silent no-op.
- **Pure first, tests-first.** Each phase's decision logic is a pure function with
  its own test file; the IO shell around it stays thin enough to read.
- A phase is done when it is **committed green** — `pnpm typecheck`, `pnpm lint`,
  `pnpm -r test` with the **count moved** (baseline **699**, `pnpm test:count`),
  and the four smokes still passing — with a 3-line summary and an explicit
  `deviation:` field (empty = none).
- **Verify a subagent's claims, never its report.** Run the gates yourself, and
  `ListAgents` before declaring anything complete.

## Phases

### P0 — the pure ports (no wiring)

The highest-value artifact in the rewrite, and it translates mechanically.

- `extensions/agents-core/src/state.ts` — `AgentState`, `StateTransition`
  (`state`, `reason?`, `clearTitle`, `applied`, `heldForBackground`,
  `turnFinished`). Vendor-blind: no Claude event name appears here.
- `extensions/claude-code/src/stop-policy.ts` — `applyEvent(...)` and
  `sessionEventAccepted(...)`, ported from `spike/seam1/Sources/StopPolicy.swift`
  with `viewing` **as a parameter** (already correct in v1 — keep it that way).
  The ordering guard, the background-`Stop` suppression and the viewing landing
  are all deliberate; do not "fix" them.
- Tests translated from `spike/seam1/Tests/StopPolicyTests.swift`, plus the
  negative controls it carries.

Nothing is registered, nothing is wired. Exit: the count moves and the two files
have no import outside `@shepherd/sdk`.

### P1 — the kernel affordances M2 needs

All in `packages/core` + `packages/app/src/main`, all tested:

- **D1's env injection** — one `onWillCreate` in main; every session gets
  `SHEPHERD_SESSION_ID` and `SHEPHERD_EVENTS_SOCK` (+ `SHEPHERD_CONTROL_SOCK`,
  which the CLI needs in M4 and costs nothing here). The ingress doc comment is
  corrected in this commit (D9).
- **D5's `SessionHost.foregroundProcess`** + the `sessions.list` command.
- **D2's `session.viewing` topic** — `ViewingResolver` gains a bus publisher for
  edges on session-bound panes. One emitter; no new predicate.

Exit: a test asserts a created session's env carries its own id, and a test drives
a foreground change through `sessions.list`.

### P2 — the extension-host affordances

- **D3**: `PointRegistry` relocates to `packages/sdk` (core re-exports); the
  child's `createPoints()` becomes real, owner-recorded and dependency-gated.
- **D4**: `ActivateFn` may return an API; the runtime records exports;
  `extensions.get`/`isActive` resolve in-process, dependency-gated.
- A child-side `sessions` subset — `list()` over `command.invoke` — replacing the
  blanket `LANDS_IN('M2')` refusal for the members that now exist. **The members
  that still cannot cross a port keep refusing, with the reason updated**;
  `api.ts`'s rule that a refusal is never `undefined` is not relaxed.

Exit: `diagnostics` still passes unchanged, and a test proves a point defined by
one extension is reachable by a declared dependent and refused to a non-dependent.

### P3 — `agents-core`

- The `agents.kinds` extension point it **defines** (§7c: this is the first real
  consumer of `points.define`, and it is what makes `codex`/`opencode`
  third-party extensions rather than a fork).
- The agent registry, keyed by `SessionID`; the `session.viewing` subscription
  (D2); the state → attention mapping (D6); `agents.stateChanged` on the bus.
- The **reconciliation sweep** (D5), on an injected clock, running only while some
  session is `working`/`blocked`, demoting with a logged reason.
- Its exported `AgentsAPI` (`registerKind`, `stateOf`, `onTurnFinished`).
- Manifest: `sessions`, `storage`, **`attention`** — and it is the only manifest in
  the repo that declares the last one (D7).

### P4 — `claude-code`

- Manifest: `dependencies: ['shepherd.agents-core']`, permissions `sessions` +
  `storage`, **no `attention`** (D7). Activation ordering comes free from
  `ExtensionRegistry`.
- Registers the `claude-code` kind: `detect` (foreground process name), the state
  machine wrapping P0's `applyEvent`, and the ownership lock (D8).
- Subscribes `claude.hook`; splits `ownerClaudeSessionID` / `resumeSessionID`.
- **The plugin**: `hooks.json` + a pure-bash `report.sh`. One `jq -cn` builds the
  whole envelope, and **field extraction moves to TypeScript** — the hook's stdin
  rides whole as `payload.hook`, which deletes v1's per-event `jq` filters, its
  hand-rolled escaper (which missed newlines, making the event invalid JSON and
  therefore *silently dropped*), and its double-encoded `payload`. No `python3`,
  no `node` — ADR 0004: ~50ms of startup put `PreToolUse` behind `Stop` and
  flipped the state, and node's ~40ms would do it again.
  Three details settled here so nobody re-derives them:
  - `curl --max-time 2`. Hooks are synchronous, so **the observer must not be able
    to stall the observed** (review §Ugly-4).
  - unparseable stdin ⇒ `hook: null`, envelope still sent. Never lose the event.
  - `seq` is a per-session counter file beside the socket, plain
    read-increment-write — stock macOS has no `flock`, and `seq` exists for gap
    *detection*, so a lost increment is visible rather than harmful.
- Plugin install as a command, porting `ClaudePluginInstaller`'s five-case
  classification: **create or repair, never replace** (ADR 0005). Installs at
  `~/.claude/skills/shepherd-v2`, so v1's global plugin is untouched (D9).

### P5 — the visual, the alert channel, and the M2 smoke

This is the phase the milestone exit is measured on.

- **Topic forwarding to the renderer**, as a generic table in main; its first
  entry is `agents.stateChanged`. The mechanism is generic; only the entry names
  an extension's topic, and that table is what M3's declarative view
  contributions replace. Recorded as a deviation, with that sentence.
- **The indicator**: a per-pane dot + industrial micro-label (`WORKING`,
  `BLOCKED`) in the state's accent colour. Flock rule 8 keeps "plain dots as the
  micro fallback", so this is rule-compliant now and the sheep silhouette lands
  when the art does — **M2 is not blocked on artwork**. Fixed-height row;
  attention never changes a row's size (rule 9, and v1 reverted exactly that).
- **Dock badge** from `attention.count()`; **banner/chime** from `decide()`, driven
  by the agent-state event (D6).
- **`pnpm smoke:m2`** against the real Electron binary: boot → create a session →
  POST a hook sequence over `hooks.sock` with `curl` (a stub agent — the wire is
  what is under test) → assert the indicator changed, the badge moved, and a
  `Stop` under a viewed pane lands `idle` while one on an unviewed pane lands
  `needsCheck`. **Unit tests cannot tell you a wire exists** — v1's LAN bug was
  every unit correct and `acceptBridged` a silent no-op on an optional chain.
- Plus one **manual verification with a real `claude`**, which no smoke can stand
  in for, reported honestly.

### P6 — the headless seam (§7c)

`capabilities` per kind, the **normalized** event union (`text`, `tool-call`,
`tool-result`, `turn-start`/`turn-end`, `error`, `usage`), the **`raw`**
passthrough beside it, and a typed error — never a hang — when a caller asks a
kind for something it does not declare.

Scoped honestly: **`complete` (one-shot) ships; `stream` (incremental) needs a new
wire-frame family** (create/attach/data/kill across the port) and lands only if
P6 is comfortable. Core-design §7's M2 line omits this seam entirely and §7c
decided its *shape*, not its date — so **the milestone exit does not depend on
P6**, and if it slips it slips as a named deviation rather than holding M2 open.

### P7 — ADRs

The probe (foreground process as the sweep's input), D1 (who injects correlation
env), D3+D4 (points and cross-extension APIs run in the child), D6 (agent state
and attention are two channels), D9 (the env var rename and v1 coexistence).

## Out of scope for M2

Tasks, worktrees, `TaskRootSynth`, the composer, the sidebar tree (M3). Workbench,
remote, nudges, onboarding, packaging. `ProcessAPI` and `SecretStore`
implementations. The `onView:` activation event. Presence sensing — `away` stays a
`decide()` parameter that main passes `false`, per §7d, which explicitly dates
that work to post-M4.

**Resume is deliberately half a feature, and the half is named.** Layout
persistence is unwired on purpose (`main/index.ts` says why: a restored tree would
make the smokes non-deterministic), so there is **nothing to restore into**. M2
captures `resumeSessionID` and builds the seeding seam; the restore that consumes
it lands with layout persistence in M3. Saying so here stops an executor building
a restore path with no caller.

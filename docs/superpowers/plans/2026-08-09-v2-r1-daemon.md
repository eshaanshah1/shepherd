# R1 — the session daemon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Sessions leave the Electron main process, so quitting or updating the
app no longer kills a running agent — and the renderer becomes the *first* client
of the attachment protocol rather than its only privileged consumer.

**Architecture:** A `shepherdd` daemon owns `SessionHost`. It is the **Electron
binary re-executed with `ELECTRON_RUN_AS_NODE=1`**, spawned detached, speaking a
framed binary protocol over a unix socket. Electron main keeps the layout,
commands and extensions, and holds a `SessionClient` that satisfies the same
`SessionHostLike` interface `SessionBridge` already takes — so the bridge, the
renderer and every smoke are unchanged by the move itself.

**Design:** [`../specs/2026-08-09-v2-attachment-and-remote-design.md`](../specs/2026-08-09-v2-attachment-and-remote-design.md) §2 D2
**Depends on:** R0 (`PtyFanout.attach` is already the whole client contract).

## Global Constraints

- `env -u NODE_OPTIONS` on every Electron command.
- `tooling/eslint/boundaries.js` IS the architecture diagram.
- Bytes, not strings, on the pty path.
- Failures are typed `Result` values, never throws.
- Node `>=25.2.1 <26`, pnpm `>=10.28.0`.

## Probe findings (measured 2026-08-09, before planning)

- **node-pty loads under `ELECTRON_RUN_AS_NODE=1`** — Electron 43.3.0, node
  24.18.1. So the daemon is the same binary against the same ABI, and ADR 0021's
  "no native rebuild per Electron bump" is preserved. A plain-node daemon would
  have needed a second node-pty build.
- **A detached child outlives its Electron parent** — reparents to `ppid 1`, and
  its pty children keep running. This is the whole milestone in one measurement:
  without it, "a UI restart does not kill your agents" is unbuildable this way.

## D3 — the decision this milestone forces

**Recorded as [ADR 0035](../../../.claude/adr/0035-v2-a-session-outlives-the-app-so-a-pane-must-be-able-to-find-it-again.md)**,
because it overturns reasoning written into two files. Summary below; the ADR has
the argument.

`layout/store.ts` currently says:

> A restored root comes back with **fresh pane ids and no sessions**: live state
> never survives a restart, and reusing an id would let a stale binding from the
> previous run resolve to a new pane.

**That is correct only while sessions die with the app.** With a daemon it
becomes the bug: a relaunch restores panes with fresh ids, each creates a *new*
session, and the daemon's originals keep running with nothing pointing at them —
unkillable from the UI. It is exactly the defect `pane-sessions.ts` documents
("a SECOND pty per pane while the first kept running"), one process up.

**Decided: pane ids persist, and so does each pane's session binding.** The
objection the old rule was defending against — a stale id resolving to a new
pane — is answered by the thing that made the change necessary: **the daemon is
the authority on what is alive.** A restored binding is a *claim*, checked
against the daemon's inventory before it is believed:

- session still live in the daemon → the pane adopts it (the point of R1);
- session gone → the binding is dropped and the pane creates one, exactly as
  today;
- session live but claimed by no restored pane → it is an **orphan**, and the
  daemon lists it so something can adopt or reap it rather than leaking.

`initialCommand` still must not round-trip — a reattached pane must never re-run
its command — and `serialize.ts`'s comment already says why.

### Task 1: The wire protocol (pure)

**Files:** create `v2/packages/core/src/session/protocol.ts` + `.test.ts`

Frames are `[u32 length][u8 kind][payload]`. Two payload shapes only: **JSON**
for control, **raw bytes** for `data` and `write`. Byte frames never pass through
JSON — base64 would inflate the hot path by a third and the whole point of the
pty path is that bytes stay bytes.

- [ ] Write `encodeFrame` / `FrameDecoder` with tests for: a frame split across
      chunk boundaries, several frames in one chunk, a zero-length payload, a
      length larger than the cap (refused as a typed error, never buffered
      unboundedly — an unbounded decoder is a memory DoS from a socket).
- [ ] Message kinds, as a const table, both directions:
      `create | attach | detach | write | paste | resize | kill | list | screen | setViewport | snapshot | hello`
      and daemon→client `data | exit | ok | err | event`.
- [ ] Every request carries a `seq`; every response echoes it. Tests: a response
      to an unknown `seq` is dropped and logged, never matched to the wrong
      caller.
- [ ] Commit.

### Task 2: The daemon

**Files:** create `v2/packages/daemon/` (`package.json`, `src/main.ts`,
`src/server.ts`, `src/server.test.ts`); modify `boundaries.js`

- [ ] `packages/daemon` may import `@shepherd/core` + `@shepherd/sdk` + stdlib
      + `node:net`. **No electron** — it runs as node. Add the boundary rule with
      its reason.
- [ ] `Server` owns one `SessionHost`, accepts connections, and maps each frame
      onto a host call. One attachment per (connection, session).
- [ ] A connection dropping detaches its viewers and **kills nothing**. This is
      R0's rule at the process boundary and it is the milestone's whole claim.
- [ ] `hello` carries a protocol version; a mismatch is refused with a typed
      error naming both versions — a daemon left over from an older build must
      say so rather than misparse.
- [ ] Single instance: refuse to take over a socket a live process is serving
      (core's `ingress` already does exactly this — reuse its check, do not
      write a second one).
- [ ] Idle exit: with no connections **and no sessions**, exit after a grace
      period. With sessions, never — that is the point.
- [ ] Commit.

### Task 3: `SessionClient` in main

**Files:** create `v2/packages/app/src/main/session-client.ts` + test; modify
`v2/packages/app/src/main/index.ts`

- [ ] `SessionClient` satisfies `SessionHostLike` (`session-bridge.ts` already
      defines it) so `SessionBridge` is untouched. The one shape change: `attach`
      is already sink-based and async-delivering after R0, so it fits as is.
- [ ] Spawn-on-demand: connect; on ECONNREFUSED/ENOENT spawn the daemon
      detached (`process.execPath` + `ELECTRON_RUN_AS_NODE=1`) and retry with
      backoff to a deadline.
- [ ] Reconnect: on socket close, retry with backoff; re-attach every live
      viewer, each of which is handed a fresh screen by R0's snapshot. **A
      reconnect must not create sessions.**
- [ ] Commit.

### Task 4: Reattach across a restart (D3)

**Files:** modify `v2/packages/core/src/layout/serialize.ts`,
`v2/packages/core/src/layout/store.ts` + tests

- [ ] Persist the pane id and its `sessionId`.
- [ ] On restore, ask the daemon which sessions are live; adopt the ones that
      are, drop the bindings that are not.
- [ ] Report orphans (live, unclaimed) rather than leaking them.
- [ ] Tests: a restored pane with a live binding adopts and does NOT create; with
      a dead binding it creates exactly one; `initialCommand` never round-trips.
- [ ] Commit.

### Task 5: The resume ladder (ADR 0035 §2, §3)

**Files:** modify `extensions/claude-code/src/kind.ts`,
`extensions/agents-core/src/*`, `extensions/tasks/src/model/launch.ts`,
`extensions/tasks/src/index.ts` + tests

Rung 2 of the ladder: when the pty is genuinely gone, a restored pane comes back
as an agent rather than a bare shell.

- [ ] `AgentKind` gains a launch-command seam beside `capabilities`;
      `claude-code` implements it as `claude --resume <target>`. This is the
      **only** package where that string may appear.
- [ ] `agents-core` exposes it vendor-blind, next to `resumeTarget`.
- [ ] `tasks` deletes `AGENT_BINARY` + `planResume` and consumes the seam. A
      test asserts `claude` appears in no file under `extensions/tasks/`.
- [ ] Core carries the command as a restored pane's `initialCommand`.
- [ ] **The negative control that matters:** a pane that reattached must NOT
      also resume. Two agents in one pane is the failure this prevents, and a
      test that only checks the resume path would not see it.
- [ ] Commit.

### Task 6: The live run — `smoke:daemon`

**Files:** create `v2/packages/app/src/main/smoke-daemon.ts`,
`v2/tooling/scripts/smoke-daemon.mjs`; modify `smoke-registry.ts`, `package.json`

The gate, and the only thing that actually proves the milestone:

- [ ] Launch the app, open a pane, run a marker command.
- [ ] Record the daemon pid and the pty pid. **Quit the app.**
- [ ] Assert both are still alive.
- [ ] Relaunch, and assert the pane **adopts** the same session id — the marker
      is still on its screen, and the live session count did not double.
- [ ] Assert an explicit `layout.close` still kills the pty (the negative
      control: surviving a quit must not mean surviving a close).
- [ ] Kill the daemon, relaunch, and assert the pane comes back **resumed**
      rather than reattached — rung 2 — and that exactly one agent is running
      in it.
- [ ] Commit.

## Done when

Quitting and relaunching the app leaves every agent running and every pane
reattached, `pnpm typecheck && pnpm lint && pnpm -r test` are clean, and all
eight smokes pass.

## R1 — done, 2026-08-09

All six tasks landed. **1546 tests**, typecheck + lint clean, and **eight of nine
smokes green** (`smoke:m3` is the pre-existing composer regression on the branch
this was cut from; `smoke:isolation` fails on `master` too).

`smoke:daemon` is the gate, and it passes: same pane id, same session id, **same
pty pid** across a full quit and relaunch, with the marker still on its screen
and no second pty created.

### What changed from the plan

- **`SessionHostLike` grew rather than staying as it was.** The plan assumed
  `SessionBridge`'s existing interface covered main's use of the host; it did
  not. `onWillCreate`, `screen`, `snapshot`, `setViewport`, `foreground`, `has`
  and `dispose` all had to join it, and `screen`/`foreground` are typed as
  value-or-promise so one signature serves both transports.
- **`registerSessionCommands` was narrowed to a `SessionInventory` port**, and
  its handler made async. `sessions.list` carries each session's foreground
  process, which is a field read in process and a round trip over a socket.
- **The daemon has to be bundled.** Node's type stripping refuses files under
  `node_modules`, so it cannot be launched from source.
- **Rung 2 of the resume ladder is complete for TASKS only.** A bare pane whose
  pty did not survive still restores as a shell. Giving it a resume command
  needs a per-pane restore hint that extensions write and core persists, and
  that API does not exist — recorded rather than half-built (ADR 0031's rule).

### What the live runs taught

Seven defects, none of which a unit test could have found:

1. **A write overtook its own create** — `#request` awaited the connection
   before sending while `write` sent synchronously, so the daemon dropped input
   for a session it had not made yet. Presented as "the marker never appears".
2. **The daemon socket ignored `--shepherd-support`**, so every smoke and
   `pnpm dev` would have driven the daily app's ptys.
3. **The daemon could not be loaded from source** (type stripping, above).
4. **`app.getAppPath()` returns `out/`**, not the package root, so both branches
   of the entry resolution pointed at paths that never existed.
5. **A detached child has nowhere to say why it died** — 3 and 4 both surfaced
   only as "did not come up within 10000ms". `SHEPHERD_DAEMON_STDIO=inherit`
   exists now, and found 4 immediately.
6. **`pkill -f --socket=…` matches nothing**, silently: a pattern starting with
   `--` is parsed as an option. The daemon was never being killed, and the
   assertion read as "it does not clean up its ptys" when it does.
7. **A second local viewer got no replay**, because main is one daemon client
   and `attach` is deduplicated per client. `RESPONSE.snapshot` is its own frame
   kind now so a late viewer can be handed a screen the others do not get.

And `exec cat` bit twice more — the seeded pane echoes keystrokes and runs
nothing, so a `printf` appears twice and executes zero times.

### What R2 inherits

The protocol is framed, versioned, and has one implementation on each side that
is already exercised across a process boundary. `SessionServer` is socket-free
and takes a `Connection`, so a TLS transport is a second implementation of that
interface rather than a change to the server. Viewport arbitration is already
per-connection, which is exactly what a phone needs.
